# URD — In-app tutorial, screenshot manual, video manual
Date: 2026-09-23   Status: APPROVED (2026-09-23)

## 1. Problem
Every system cloned from the template needs user guidance: an in-app walkthrough, a printable
manual, and a video. Doing these by hand means taking screenshots again and re-recording every
time the UI changes, so they go stale.

## 2. Goal
One source of help content per page, `src/data/help` (already used by the chatbot's
`get_help`), drives three outputs:
1. an in-app tour,
2. a `/manual` page with a PDF version,
3. a narrated Thai video manual,
all regenerated by one command after the UI changes.

## 3. Users & stakeholders
| Role | Need | Signs off? |
| --- | --- | --- |
| End user (staff) | Learn a page in the moment, look things up later | — |
| System developer (clones template) | Add steps per page, regenerate manual and video with one command | yes |
| Unit owner / trainer | PDF to distribute and a video for training | yes |

## 4. Current workflow
None. `src/data/help` has one example page, and nothing renders it except `get_help`.

## 5. Inputs available / missing
| Input | Have? | Notes |
| --- | --- | --- |
| Help content per page (`helpByPage`, steps with CSS `target`) | yes | only `/` for now; add examples |
| Logged-in session for capture | yes | mint a cookie with NEXTAUTH_SECRET (same as check.mjs) |
| TTS | chosen | Edge TTS by default (free, th-TH voices, no key); ElevenLabs if `ELEVENLABS_API_KEY` is set |
| ffmpeg / Playwright | to check | dev dependencies, local only |

## 6. Deliverables
- Tour: a "สอนใช้งาน" button on the navbar. It plays automatically the first time a user opens a page that has help, remembers that per page in the browser, highlights `data-tour` targets, and supports keyboard and Esc.
- `/manual` page: every page's help, with screenshots, in print-friendly layout, plus a "ดาวน์โหลด PDF" option.
- A capture script (`pnpm manual:capture`): Playwright logs in, visits each help page, screenshots each step with its target highlighted, and writes `public/manual/*` and a PDF.
- A video script (`pnpm manual:video`): Playwright records the tour per page; narration is TTS of each step's text, synced to steps, with Thai subtitles; the result is `public/manual/video/*.mp4`, playable on `/manual`.
- Docs plus a skill or CLAUDE.md rule: "add help steps when you add a page".

## 7. Success criteria (observable)
- SC1: Opening a page with help for the first time starts the tour. Reloading does not restart it. The button restarts it.
- SC2: Every tour step whose target is missing is skipped without errors. The tour is reachable by keyboard and Esc closes it.
- SC3: `pnpm manual:capture` produces one PNG per step and a PDF, with no manual login.
- SC4: `/manual` renders every page in `helpByPage` with its images, and access control follows the existing rules (it needs a login).
- SC5: `pnpm manual:video` produces an MP4 per page, with Thai narration (Edge TTS, no key) and subtitles, where each step's audio lines up with its highlight.
- SC6: Setting `ELEVENLABS_API_KEY` switches the voice to ElevenLabs without changing code.
- SC7: A cloned system adds one page's help in one file and regenerates everything with two commands.

## 8. Out of scope & risks
- Out: editing the manual in a CMS, multiple languages, a hosted video platform, recording on CI/Linux servers (local Mac/dev machine only).
- Risk: Edge TTS is an unofficial endpoint and can break. Mitigation: a pluggable provider, with ElevenLabs as the fallback.
- Risk: screenshots can contain real personal data. Mitigation: capture with a demo user and demo data only; document this under PDPA.
- Risk: big binaries in git. Mitigation: generated files go in `public/manual/`, which is gitignored by default; the choice to commit them is documented.
